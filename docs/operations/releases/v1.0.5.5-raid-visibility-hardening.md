# v1.0.5.5 RAID Visibility Hardening

Date: 2026-06-12

## Summary

v1.0.5.5 applies the centralized project visibility model to global RAID reads and hardens legacy RAID mutation endpoints with the existing RAID permissions.

Before this release, `GET /raid` and `GET /risks` loaded records globally. Frontend Risks and Issues screens consume `GET /raid`, so users with access to only a subset of projects could still see unrelated RAID records through global aggregation.

## APIs Updated

| API | Change |
| --- | --- |
| `GET /raid` | Filters risks, issues, assumptions, and dependencies to visible project ids from `ProjectVisibilityService`. |
| `POST /raid` | Now requires `raid.create`. |
| `GET /risks` | Filters risks to visible project ids from `ProjectVisibilityService`. |
| `GET /risks/:id` | Returns `404` when the actor cannot view the risk project. |
| `POST /risks` | Now requires `raid.create`. |
| `PATCH /risks/:id` | Now requires `raid.update` and checks project visibility before update. |
| `DELETE /risks/:id` | Now requires `raid.delete` and checks project visibility before delete. |

Project workspace scoped endpoints were already project-visibility gated by `ProjectsService`.

## Visibility Rules

| Role | RAID Visibility |
| --- | --- |
| `SUPER_ADMIN` | RAID from all projects |
| `Admin` | RAID from all projects |
| `Program Manager` | RAID from all projects |
| `Portfolio Manager` | RAID from all projects |
| `Executive` | RAID from all projects, read-only |
| `Project Manager` | RAID from owned, managed/member, or task-assigned projects |
| `Delivery Lead` | RAID from owned, managed/member, or task-assigned projects |
| `Team Member` | RAID from member or task-assigned projects |
| `Partner` | RAID from assigned/member projects only |
| `Customer` | RAID from assigned/member projects only |
