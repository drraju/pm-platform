# v1.0.5 Project Teams & Task Operations

## Features

- Added project team management APIs and workspace controls for adding, updating, and removing project members.
- Added task operation fields for remarks, percent complete, planned dates, and actual dates.
- Enhanced My Tasks with inline status, remarks, percent complete, and reassignment updates.
- Added Project Workspace Tasks tab with create, edit, reassign, and delete task operations.
- Added Project Workspace Project Team tab with team add, remove, and role update operations.
- Enforced project/task operation policy for program managers, project managers, project owner/manager members, and assigned team members.

## Root Cause Of Missing CRUD UI

- The initial v1.0.5 work completed backend APIs, DTOs, permissions, and API client bindings, but `ProjectWorkspaceTasks` remained a mostly read-only task table.
- Project task create/edit/reassign/delete flows were not fully represented as user workflows in the workspace.
- The first task dialog only covered a subset of the requested fields and did not include planned dates, remarks, percent complete, delete confirmation, or toast feedback.
- The Project Team management controls existed as a component but needed to be exposed as a first-class workspace tab and permission-aware workflow.

## User Workflows

- Project Manager or Program Manager opens a project, selects the Tasks tab, creates a task, assigns it to a project team member, and sets title, description, assignee, status, priority, planned start, planned end, due date, remarks, and percent complete.
- Project Manager or Program Manager edits a project task from the Actions column, updates task details, changes assignee/status/priority/planned dates/remarks/percent complete, and saves.
- Project Manager or Program Manager deletes a project task from the Actions column after confirming the delete modal.
- Project Manager or Program Manager selects the Project Team tab, adds a user to the project, changes role in project, or removes a member.
- Team Member opens My Tasks, updates assigned task status, percent complete, remarks, and reassigns only to another project team member.
- Executive users see project tasks without task/team management buttons.
- Users receive success and error toast notifications after task and team operations.

## APIs

- `GET /projects/:id/members`
- `POST /projects/:id/members`
- `PATCH /projects/:id/members/:memberId`
- `DELETE /projects/:id/members/:memberId`
- `GET /projects/:projectId/tasks`
- `POST /projects/:projectId/tasks`
- `PATCH /projects/:projectId/tasks/:taskId`
- `DELETE /projects/:projectId/tasks/:taskId`
- `PATCH /tasks/:id`

For backward compatibility, member update/delete lookup accepts either the project membership id or the older user id value.

## Permissions

- `project.team.manage`
- `task.create`
- `task.update`
- `task.delete`
- `task.reassign`
- `task.comment`

Program Manager, Project Manager, and project owner/manager members can manage project teams and full task operations. Assigned team members can update their own task status, remarks, percent complete, and assignee, with reassignment restricted to users already on the project team.

Frontend permission behavior:

- Program Manager: create, edit, reassign, delete project tasks; manage project team.
- Project Manager: create, edit, reassign, delete project tasks; manage project team.
- Project Owner or Manager member: create, edit, reassign, delete project tasks; manage project team.
- Team Member: update assigned tasks from My Tasks; can reassign assigned tasks to project team members.
- Executive: view-only task and team experience; management buttons are hidden.
