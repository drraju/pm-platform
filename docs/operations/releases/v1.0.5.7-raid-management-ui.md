# v1.0.5.7 RAID Management UI

Date: 2026-06-13

## Summary

v1.0.5.7 completes user-facing RAID management. Risks, Issues, Assumptions, and Dependencies can now be created, edited, and deleted from authorized UI surfaces. Project Workspace now includes dedicated RAID tabs instead of read-only register cards.

## Screens Added or Updated

| Screen | Change |
| --- | --- |
| Global RAID | Full create/edit/delete for risks, issues, assumptions, and dependencies where authorized. |
| Risks | Risk-focused CRUD page. |
| Issues | Issue-focused CRUD page. |
| Project Workspace | Added Risks, Issues, Assumptions, and Dependencies tabs with CRUD actions. |

## APIs Used

| UI Action | API |
| --- | --- |
| List global RAID | `GET /raid` |
| Create RAID item | `POST /raid` |
| Edit RAID item | `PATCH /raid/:id` |
| Delete RAID item | `DELETE /raid/:id` |
| Project risks | `GET /projects/:id/risks` through project details loading |
| Project issues | `GET /projects/:id/issues` through project details loading |
| Project assumptions | `GET /projects/:id/assumptions` through project details loading |
| Project dependencies | `GET /projects/:id/dependencies` through project details loading |

## Fields Implemented

| Type | Fields |
| --- | --- |
| Risk | `title`, `description`, `probability`, `impact`, `owner`, `mitigationPlan`, `status` |
| Issue | `title`, `description`, `owner`, `dueDate`, `resolutionPlan`, `status` |
| Assumption | `title`, `description`, `owner`, `validationStatus`, `validationNotes`, `status` |
| Dependency | `title`, `description`, `owner`, `dependsOn`, `dueDate`, `status` |

## Permission Behavior

| Role | Create | Update | Delete | UI Behavior |
| --- | --- | --- | --- | --- |
| Program Manager | Yes | Yes | Yes | Full CRUD |
| Project Manager | Yes | Yes | Yes | Full CRUD |
| Delivery Lead | Yes | Yes | No | Create/Edit only |
| Team Member | Yes | Own items | No | Create/Edit own items only |
| Executive | No | No | No | Read only |
| Customer | No | No | No | Read only |
| Partner | No | No | No | Read only |

Backend enforces `raid.create`, `raid.update`, and `raid.delete`. The service also checks project visibility and uses legacy granular keys where available:

- `raid:update:any` for full update
- `raid:update:own` for owner-scoped update
- `raid:delete` / `raid.delete` for delete
