# v1.0.5.6 Executive Experience Validation

Date: 2026-06-12

## Summary

v1.0.5.6 restores the Executive user experience by adding a real `/executive` page, exposing the Executive navigation item through permission-based navigation, and ensuring project creation is hidden from users without `project.create`.

Previously `/executive` immediately redirected to `/dashboard`, and the app shell did not include an Executive navigation item.

## Screens Implemented

| Screen | Status | Notes |
| --- | --- | --- |
| Dashboard | Existing | Visible with `dashboard.view`. |
| Executive | Implemented | Read-only portfolio health, RAID exposure, overdue task, and attention project summary. |
| Portfolio | Existing | Visible with `portfolio.view`. |
| Projects | Existing | Visible with `project.read`; create button now requires `project.create`. |

## Executive Navigation

Expected Executive navigation:

| Navigation Item | Permission | Executive Result |
| --- | --- | --- |
| Dashboard | `dashboard.view` | Visible |
| Executive | `executive.view` | Visible |
| Portfolio | `portfolio.view` | Visible |
| Projects | `project.read` | Visible |
| My Tasks | `task.update` or `task.comment` | Hidden |
| Risks | `raid.read` | Visible |
| Issues | `raid.read` | Visible |
| Users | `user.manage` or `role.manage` | Hidden |
| Notifications | `notification.read` | Visible |

The requested minimum Executive navigation is Dashboard, Executive, Portfolio, and Projects. Risks, Issues, and Notifications remain visible because the seeded Executive role has read permissions for those areas.
