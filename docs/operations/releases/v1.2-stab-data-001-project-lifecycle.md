# v1.2 STAB-DATA-001 Project Lifecycle

## Summary

STAB-DATA-001 replaces permanent project deletion as the default project removal
workflow with an enterprise-safe lifecycle.

## Behavior

- Active projects remain the default list view.
- Archived projects are hidden from normal project lists unless archived records
  are explicitly requested.
- `DELETE /projects/:id` archives a project rather than physically deleting it.
- `POST /projects/:id/archive` moves a project to archived status while
  preserving related records.
- `POST /projects/:id/restore` restores an archived project to active portfolio
  visibility without changing related records.
- `DELETE /projects/:id/purge` permanently removes project-owned records only
  when the project is already archived.

## Security And Data Integrity

- Archive uses existing project delete authorization.
- Restore uses existing project update authorization.
- Permanent purge is restricted to platform administrators.
- Normal create and update requests cannot set `archived` directly; archive and
  restore endpoints own lifecycle transitions.
- Purge deletes project-owned records in a transaction and uses the existing
  database purge guard for immutable baseline records.
