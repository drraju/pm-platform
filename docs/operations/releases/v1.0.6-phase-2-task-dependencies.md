# v1.0.6 Phase 2 Task Dependencies

## Summary

This change implements Phase 2 of the `v1.0.6` planning foundation.

Delivered in this phase:

- `task_dependencies`
- dependency validation rules
- project-scoped dependency CRUD APIs
- backend tests

Deferred from this phase:

- baselines
- timeline APIs and UI
- Gantt APIs and UI

## Scope Delivered

### Dependency Model

The backend now supports explicit task dependency edges with:

- predecessor task
- successor task
- dependency type:
  - `FS`
  - `SS`
  - `FF`
  - `SF`
- `lag_days`

Dependencies are stored in the new `task_dependencies` table with:

- soft delete support
- active-edge uniqueness on `(predecessor_task_id, successor_task_id)`
- audit columns aligned with the rest of the platform

### Validation Rules

The backend now enforces:

- predecessor and successor must be different tasks
- both dependency endpoints must belong to the same project
- summary tasks cannot be dependency endpoints
- only leaf tasks and milestones can be dependency endpoints
- duplicate active edges between the same tasks are rejected

### API Surface

Project-scoped dependency APIs are now available:

- `GET /projects/:projectId/task-dependencies`
- `GET /projects/:projectId/task-dependencies/:dependencyId`
- `POST /projects/:projectId/task-dependencies`
- `PATCH /projects/:projectId/task-dependencies/:dependencyId`
- `DELETE /projects/:projectId/task-dependencies/:dependencyId`

## Notes

- This phase adds the write-side dependency network only.
- Baselines remain out of scope.
- Timeline and Gantt UI remain out of scope.
- Critical path calculation is still deferred.
