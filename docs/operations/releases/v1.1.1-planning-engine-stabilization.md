# v1.1.1 Planning Engine Stabilization

## Purpose

Define the v1.1.1 stabilization release for the Planning Engine.

## Scope

This document covers release objectives, planned features, architecture changes, database considerations, known issues, and future work before Resource Management begins.

## Audience

Engineering leads, product managers, QA engineers, release managers, PMO stakeholders, and implementation teams.

## Overview

v1.1.1 should focus on correctness and enterprise readiness rather than major new functionality. The release should stabilize scheduling logic, dependency validation, critical path calculations, resource load foundations, accessibility, and performance.

## Contents

### Objectives

- Replace foundation critical path indicators with CPM-based calculations.
- Enforce dependency constraints during schedule edits.
- Prevent circular dependencies transactionally.
- Make schedule snapshot writes atomic.
- Improve large-plan rendering and API efficiency.
- Prepare resource calculations for Resource Management.

### Features

| Feature | Summary |
| --- | --- |
| CPM calculation | Early/late dates, total float, and critical task flags. |
| Schedule validation | Dependency-aware validation for task date changes. |
| Transactional recalculation | Atomic update of schedules, dependencies, and snapshot metadata. |
| Resource load foundation | Allocation demand compared against capacity by date. |
| Large-plan performance | Rendering and API improvements for 500+ tasks. |
| Accessibility improvements | Keyboard alternatives for Gantt interactions. |

### Architecture Changes

- Extract planning engine domain services.
- Move recalculation out of workspace read requests.
- Add optimized workspace read model queries.
- Add transaction boundaries around multi-table planning writes.
- Introduce frontend virtualization or viewport culling for Gantt rows.

### Database Changes

Potential changes include:

- Additional indexes for schedule graph traversal.
- Capacity and allocation query indexes.
- Optional recalculation metadata fields.
- Constraint improvements for schedule and dependency integrity.

### Known Issues

- Current Planning Workspace is a foundation implementation.
- Resource capacity entities exist but are not yet a full resource management model.
- Portfolio-level dependency planning is still future work.
- Schedule and execution task synchronization rules need explicit product decisions.

### Future Work

- Resource Management.
- Portfolio planning.
- Cross-project dependencies.
- Scenario planning.
- Baseline variance reporting.
- Advanced calendar support.
