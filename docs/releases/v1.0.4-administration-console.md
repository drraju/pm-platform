# v1.0.4 Administration Console

## Summary

v1.0.4 introduces a protected administration console for managing users, roles, permissions, role-permission assignments, and project memberships through the application UI and API.

## Admin Architecture

Backend:

- `AdminModule`
- `AdminController`
- `AdminService`
- `AdminGuard`

Frontend:

- `/admin`
- `/admin/users`
- `/admin/roles`
- `/admin/permissions`
- `/admin/role-matrix`
- `/admin/projects`

All admin APIs are protected by JWT authentication and `AdminGuard`. The guard requires the authenticated user role name to be `Admin`.

## Admin User

Default seed administrator:

```text
Username: admin@example.com
Temporary password: Admin123!
```

Password reset procedure:

1. Sign in as `admin@example.com`.
2. Open `/admin/users`.
3. Use Reset on the target user.
4. Provide the temporary password to the user through an approved internal channel.
5. The user should change the password after first sign-in when the password-change flow is available.

## Role Model

Default roles:

- Admin
- Executive
- Portfolio Manager
- Program Manager
- Project Manager
- Team Member
- Partner
- Customer

Roles include a `status` field so administrators can disable custom roles without deleting historical assignments.

## Permission Model

Permissions are persisted in the `permissions` table and grouped by category:

- Dashboard
- Portfolio
- Executive
- Projects
- Tasks
- RAID
- Users
- Roles
- Administration
- Notifications

Role permission assignments are stored in `role_permissions`.

Authorization uses persisted role permissions when they exist. Bootstrap defaults remain as a fallback for roles without saved assignments, and Admin receives full platform permissions.

## Matrix Design

The Role-Permission Matrix UI displays:

- Permissions as rows.
- Roles as columns.
- Checkbox assignments.
- Save operation that replaces each role's permission assignments atomically at the API level.

Permission inheritance is supported operationally by cloning a role and adding or removing permissions in the matrix.

## Security Controls

- `/admin/*` routes are hidden unless the user has admin permissions.
- `/admin/*` API routes require the Admin role.
- Admin can manage users, roles, permissions, role-permission assignments, and project memberships.
- Permission changes are persisted and used by the authorization service.
- Password reset stores a bcrypt hash and does not return password hashes in API responses.
