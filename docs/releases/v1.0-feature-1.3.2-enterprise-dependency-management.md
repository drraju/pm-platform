# Release 1.0 — Enterprise Dependency Management

## Summary

Feature 1.3.2 adds an enterprise-grade, read-only dependency analysis boundary over the existing canonical `TaskDependency` aggregate. It provides health, blocked-state, and bounded downstream-impact projections while preserving Planning and Scheduling authority.

## New Capabilities

- Deterministic dependency health with explicit reasons.
- Derived task blocking state independent of workflow status.
- Cycle-safe downstream impact traversal with configurable limits.
- Stable filtering, sorting, search, and pagination.
- Visibility-aware global detail and project collection APIs.
- DTO-only public responses and complete Swagger schemas.

## API Additions

- `GET /dependencies/{dependencyId}`
- `GET /projects/{projectId}/dependencies`

See the [Enterprise Dependency API](../api/enterprise-dependencies.md) for the complete contract.

## Architecture

- `TaskDependency` remains canonical.
- `ProjectsService` remains mutation authority.
- `DependencyQueryService` is the read authority for the new projections.
- Planning remains scheduling authority.
- Portfolio remains reporting authority.
- Health, blocked state, impact, and projections are derived and non-persisted.

## Performance and Security

- Endpoint tasks are loaded in a set-based repository operation.
- Traversal is bounded, cycle-safe, deterministic, and uses a linear-time queue.
- Existing JWT, `project.read`, and project visibility policies are reused.
- Hidden and nonexistent dependency detail reads both return `404`.

## Compatibility and Deployment

- No breaking changes.
- No database migration.
- No new repository.
- Existing dependency mutation and legacy read routes remain unchanged.
- No Scheduling Engine, Planning algorithm, Portfolio calculation, or frontend change is included.

## Verification

- 104 backend suites passed.
- 633 tests passed, with 6 existing todos.
- Dependency-focused coverage reached 97.85% statements, 81.98% branches, 100% functions, and 97.69% lines during final verification.
- Feature-scoped lint, formatting, build, and diff checks passed.

## Known Limitations

- Nonzero lag/lead and legacy SF dependencies report unknown health because their scheduling mathematics are deferred.
- Large visible graphs are composed in memory before derived filtering and pagination.
- Frontend dependency-management surfaces are not part of Feature 1.3.2.
