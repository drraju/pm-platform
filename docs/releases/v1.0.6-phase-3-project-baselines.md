# v1.0.6 Phase 3 Project Baselines

## Summary

This change implements Phase 3 of the `v1.0.6` planning foundation.

Delivered in this phase:

- `project_baselines`
- `project_baseline_tasks`
- project baseline capture API
- immutable baseline enforcement

Deferred from this phase:

- timeline APIs and UI
- Gantt APIs and UI

## Scope Delivered

### Baseline Model

The backend now supports immutable project baseline snapshots with:

- a project-level baseline header
- version numbering per project
- captured timestamp and captured-by user
- current baseline flag
- per-task snapshot rows with denormalized planning data

`project_baseline_tasks` stores immutable copies of:

- task identity
- parent task identity
- task title
- task kind
- sequence number
- planned dates
- estimated hours
- percent complete

### API Surface

Project baseline capture is now available at:

- `POST /projects/:projectId/baselines`

Request body:

```json
{
  "name": "Approved Delivery Baseline",
  "status": "approved",
  "setAsCurrent": true
}
```

### Immutability Enforcement

Baseline immutability is enforced in two layers:

- no update or delete baseline APIs are exposed
- database triggers block mutation of `project_baseline_tasks`
- database triggers block destructive or structural mutation of `project_baselines`

The only allowed post-capture header change is switching `is_current` when a newer baseline is captured as current.

## Notes

- This phase captures planning snapshots only.
- Timeline and Gantt remain out of scope.
- Baseline comparison views remain out of scope.
