# v1.0.5.4 Project List Visibility Correction

Date: 2026-06-12

## Summary

v1.0.5.4 corrects scoped project-list visibility for Customer and Partner users.
The Projects page renders the direct `GET /projects` response, so visibility is
controlled by backend filtering. Customer and Partner users now see only
project-level assignments/memberships and do not receive task-assignment project
expansion.

## Root Cause

The v1.0.5.3 centralized visibility model expanded scoped visibility through
task assignments for all scoped roles. That was too broad for Customer and
Partner. Runtime testing also showed the UI displaying all projects, which means
the active runtime `GET /projects` response returned all projects or was running
a stale backend/frontend build.

Follow-up frontend tracing confirmed the Projects page renders only
`GET /projects`. To prevent stale authenticated data after role switching, API
requests now use `cache: "no-store"` and the backend emits no-store response
headers.

## API Behavior

These APIs continue to use the centralized visibility service:

- `GET /projects`
- `GET /dashboard/me`
- `GET /portfolio/summary`
- Project workspace read APIs
- Task read APIs

Project detail behavior remains unchanged: once a user can access a project,
they can see that project's tasks, RAID items, and workspace context.

`GET /tasks/my` remains restricted to tasks assigned to the authenticated user.

## Role Visibility Correction

| Role | Project List Visibility |
| --- | --- |
| Customer | Owned/member project assignments only |
| Partner | Owned/member project assignments only |
| Team Member | Owned/member projects plus projects containing assigned tasks |
| Delivery Lead | Owned/member projects plus projects containing assigned tasks |
| Project Manager | Owned/member projects plus projects containing assigned tasks |
| Program Manager | All projects |
| Portfolio Manager | All projects |
| Executive | All projects, read-only by permissions |
| Admin / SUPER_ADMIN | All projects |
