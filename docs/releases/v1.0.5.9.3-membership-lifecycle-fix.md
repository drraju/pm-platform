# v1.0.5.9.3 Membership Lifecycle Fix

## Summary

This release fixes the project membership lifecycle bug that prevented a user from being re-added to a project after a prior soft delete.

## Problem

`project_members` used both:

- soft delete via `deleted_at`
- a full-table uniqueness rule on `(project_id, user_id)`

That combination meant a removed membership row still blocked a later re-add for the same project/user pair.

## Changes

- Replaced the full unique membership constraint with a partial unique index on active rows only:
  - unique `(project_id, user_id)` where `deleted_at IS NULL`
- Updated the add-member flow to restore an existing soft-deleted membership row instead of creating a duplicate
- Preserved soft delete behavior for membership removal
- Extended project service tests to cover add, remove, and re-add scenarios

## Result

- Active memberships remain unique per project/user
- Removed members can be re-added cleanly
- Existing authorization and membership query behavior remains aligned with soft delete semantics
