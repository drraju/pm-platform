# v1.0.3 External Collaboration and Role Expansion

## Summary

v1.0.3 extends the authorization model to support internal portfolio roles and controlled external collaboration. It adds Partner and Customer roles, project membership visibility levels, and external-aware project workspace responses.

## New Roles

Internal roles:

- Executive
- Portfolio Manager
- Program Manager
- Project Manager
- Team Member

External roles:

- Partner
- Customer

Legacy delivery roles remain supported for compatibility with existing data, but new seed data uses Team Member for delivery contributors.

## Project Membership Visibility

Project memberships now include `visibilityLevel`:

- `INTERNAL`
- `PARTNER`
- `CUSTOMER`

This allows the platform to distinguish internal project members from external collaborators on the same project.

## External Collaboration Model

Partner access:

- Can access assigned projects.
- Can view project health and progress on assigned projects.
- Can view milestones and tasks assigned to them.
- Cannot access portfolio or executive dashboards.
- Cannot access project RAID endpoints.
- Cannot access unrelated projects.

Customer access:

- Can access assigned projects.
- Can view project health and milestone/progress data.
- Can view customer-assigned tasks.
- Cannot access portfolio or executive dashboards.
- Cannot access project RAID endpoints.
- Cannot access project member lists or internal user data.
- Cannot access unrelated projects.

## Security Controls

- Navigation remains permission-driven, hiding unauthorized portfolio, executive, RAID, and management routes.
- Project detail responses are filtered for external roles.
- Project task responses are filtered for external roles to assigned tasks and milestone tasks.
- Project RAID endpoints now require RAID permissions in addition to project read access.
- External roles do not receive RAID permissions.
- External project detail responses remove internal RAID, owner, and member data.

## Migration Requirements

Added migration:

```text
backend/src/database/migrations/1780848002000-AddProjectMemberVisibilityLevel.ts
```

The migration creates the project membership visibility enum and adds:

```sql
ALTER TABLE "project_members"
ADD COLUMN IF NOT EXISTS "visibility_level" project_visibility_level NOT NULL DEFAULT 'INTERNAL';
```

Run after building backend:

```bash
npm run build
npm run migration:run
```
