# Roadmap Documentation

The Roadmap folder contains planning documentation for future platform evolution.

These documents answer **when** capabilities will be delivered.

---

## Contents

Typical documents include:

* Product Roadmap
* Release Plan
* Milestone Planning
* Epic Scheduling
* Release Themes
* Version Planning

---

## Intended Audience

* Product Managers
* Delivery Managers
* Architects
* Executive Stakeholders

---

## Objectives

The roadmap provides visibility into:

* Planned capabilities
* Strategic priorities
* Release sequencing
* Delivery milestones
* Long-term platform evolution

Roadmaps are planning documents and may change as priorities evolve.

# PM Platform Roadmap

This directory is the canonical home for PM Platform roadmap documentation.

Roadmap documents describe what the product is building next. ADRs describe why
architecture decisions were made, and release notes describe what shipped.

## Current Roadmap Documents

| Document | Purpose |
| --- | --- |
| [v1.1 Roadmap](v1.1.md) | Near-term enterprise planning roadmap. |
| [Product Backlog](backlog.md) | Prioritized parking lot for planned product work. |
| [Future Roadmap](future.md) | Longer-term product direction beyond committed release planning. |

## Archived Roadmap Documents

Older roadmap drafts, beta-specific roadmap notes, and duplicate root roadmap
files are preserved under `docs/archive/roadmap/`.

## Maintenance Rules

- Keep active roadmap work in this directory.
- Move superseded roadmap drafts to `docs/archive/roadmap/`.
- Keep roadmap items aligned with product vision, release notes, and ADRs.
- Use release notes for shipped work and ADRs for architectural decisions.
