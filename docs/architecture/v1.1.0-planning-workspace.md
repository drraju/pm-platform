# v1.1.0 Planning Workspace Architecture

## Purpose

The Planning Workspace is the primary project schedule interface at
`/projects/:id/planning`. It gives project managers a split task-tree and SVG
Gantt view for schedule movement, duration changes, dependency management,
critical path visibility, and resource allocation review.

## Backend Ownership

Scheduling mutations are handled by the planning engine API and persist to
`planning_task_schedules`. They do not mutate the normal `tasks` table. Existing
project, task, authentication, dashboard, and planning rollup APIs remain
unchanged.

The workspace endpoint returns a server-owned planning read model:

- project metadata
- active schedule snapshot
- planning task schedule rows
- task dependencies
- resource allocations
- critical path task IDs

If a project does not yet have a schedule snapshot, the planning service seeds
one from existing project tasks. This bootstraps the workspace without changing
the task records.

## REST Surface

- `GET /planning/projects/:projectId/workspace`
- `PATCH /planning/projects/:projectId/task-schedules/:taskId`
- `POST /planning/projects/:projectId/dependencies`
- `DELETE /planning/projects/:projectId/dependencies/:dependencyId`
- `GET /planning/projects/:projectId/critical-path`
- `POST /planning/projects/:projectId/resource-allocations`
- `PATCH /planning/projects/:projectId/resource-allocations/:allocationId`
- `DELETE /planning/projects/:projectId/resource-allocations/:allocationId`

## Validation

The planning service prevents:

- dependency loops
- self-dependencies
- summary tasks as dependency endpoints
- summary task drag and resize
- negative task duration
- milestone duration greater than zero
- allocation to users outside the project team
- resource allocation finish dates before start dates

## Frontend Structure

- Route: `frontend/app/(app)/projects/[id]/planning/page.tsx`
- API wrapper: `frontend/features/planning`
- Main component: `frontend/components/planning/planning-workspace.tsx`

The Gantt is rendered with SVG rather than a third-party Gantt package. The
component owns view concerns only: zoom, collapse state, drag gestures, resize
gestures, and dependency form state. Schedule and dependency rules remain in the
backend.

## Gantt Capabilities

- hierarchical task tree with WBS numbering
- phase, task, and milestone symbols
- day, week, and month zoom
- draggable task bars
- duration resize handles
- milestone diamonds
- dependency connector overlay
- critical path styling
- today marker
- weekend shading
- resource allocation bands with green, amber, and red thresholds

## Future Enhancements
