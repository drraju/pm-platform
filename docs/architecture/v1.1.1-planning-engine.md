# v1.1.1 Planning Engine

## Purpose

Define the v1.1.1 architecture needed to stabilize the Planning Engine before Resource Management begins.

## Scope

This document covers critical path correctness, schedule validation, dependency graph integrity, transaction boundaries, resource calculations, API consistency, and performance requirements.

## Audience

Engineering leads, backend engineers, frontend engineers, QA engineers, architects, and product owners.

## Overview

v1.1.1 should convert the Planning Workspace foundation into a reliable planning engine. The release should avoid major new user-facing functionality and instead focus on correctness, data integrity, accessibility, and performance so future resource planning can rely on stable schedule outputs.

## Contents

### Proposed Service Decomposition

```text
PlanningService
|-- PlanningAuthorization
|-- PlanningWorkspaceQuery
|-- ScheduleSnapshotService
|-- DependencyGraphService
|-- CriticalPathService
|-- ScheduleValidationService
`-- ResourceLoadService
```

### Critical Path Service

The Critical Path Service should compute:

- Early start and early finish.
- Late start and late finish.
- Total float.
- Critical task flags.
- Driving dependency path.
- Milestone participation.

### Dependency Validation

Dependency validation should include:

- Self-reference rejection.
- Duplicate active edge rejection.
- Summary task endpoint rejection.
- Leaf-task endpoint enforcement.
- Circular dependency prevention.
- Dependency type and lag validation.
- Transaction-safe graph checks.

### Schedule Consistency

Schedule writes should validate that:

- Finish date is not before start date.
- Milestones remain zero duration.
- Dependency constraints are respected.
- Summary dates are derived from children.
- Snapshot metadata is updated with the recalculated schedule.

### Transaction Boundary

```text
User edit
  -> validate permissions
  -> lock relevant project/snapshot graph
  -> apply schedule or dependency change
  -> recalculate impacted graph
  -> persist rows and snapshot metadata
  -> commit
```

### API Design

| Endpoint Type | Direction |
| --- | --- |
| Workspace read | Return precomputed or transactionally consistent read model. |
| Schedule update | Update date/percent fields and return recalculated affected rows. |
| Dependency CRUD | Provide create, update, delete, and validation feedback. |
| Critical path | Return task IDs plus float and driving-path metadata. |
| Resource load | Return allocation and capacity projection by user/date. |

### Performance Requirements

- Support 500+ visible tasks without unusable rendering delays.
- Avoid per-row saves during read requests.
- Use indexed task and dependency maps during graph traversal.
- Add frontend row virtualization or viewport culling for the Gantt.
- Avoid full workspace reload after small edits where possible.
