# Critical Path Engine Architecture

**Status:** Approved Target Architecture

**Version:** Planning Engine v2

**Applies From:** Beta 3.4

**Last Updated:** July 2026

---

# Purpose

The Critical Path Engine calculates the project schedule using dependency relationships and planned durations.

It identifies:

- Critical Activities
- Early Start (ES)
- Early Finish (EF)
- Late Start (LS)
- Late Finish (LF)
- Total Float
- Free Float
- Project Finish Date

The engine is the scheduling authority for all future planning features including:

- Baselines
- Schedule Health
- Portfolio Reporting
- AI Schedule Analysis
- What-if Planning

---

# Design Principles

The Critical Path Engine is deterministic.

Given the same:

- Tasks
- Durations
- Dependencies
- Calendar

it must always produce the same schedule.

No UI component performs scheduling calculations.

Scheduling logic exists only inside the Planning Engine.

# Task Types

## Task

Executable work.

Contributes:

- Duration
- Dependencies
- Critical Path
- Float

---

## Summary

Scheduling container.

Does NOT participate directly in Critical Path.

Summary dates are calculated from descendants.

---

## Milestone

Zero-duration scheduling event.

Participates in:

- Dependencies
- Critical Path

Duration is always zero.

# Scheduling Algorithm

Scheduling uses the Critical Path Method (CPM).

The algorithm consists of:

1. Dependency validation
2. Topological ordering
3. Forward Pass
4. Backward Pass
5. Float calculation
6. Critical Path identification

---

# Dependency Validation

Validate:

- No circular dependencies
- Valid endpoints
- Supported dependency types

Validation occurs before scheduling.

---

# Topological Sort

Tasks are processed in dependency order.

Any cycle prevents scheduling.

---

# Forward Pass

Calculate:

Early Start (ES)

Early Finish (EF)

Rules

FS

Successor starts after predecessor finishes.

SS

Successor starts after predecessor starts.

FF

Successor finishes after predecessor finishes.

Milestones have zero duration.

Formula

EF = ES + Duration

---

# Backward Pass

Starting from project completion:

Calculate:

Late Finish (LF)

Late Start (LS)

Formula

LS = LF − Duration

---

# Float

## Total Float

Amount a task may slip without delaying project finish.

Formula

TF = LS − ES

or

LF − EF

---

## Free Float

Amount a task may slip without delaying any successor.

Future implementation.

---

# Critical Activities

A task is Critical when:

Total Float = 0

Critical activities form the Critical Path.

---

# Critical Path

The Critical Path is the longest dependency chain through the project.

Characteristics:

- Zero total float
- Determines project completion date
- Automatically recalculated after planning changes

---

# Summary Behaviour

Summary tasks never appear on the Critical Path.

Summary dates continue to derive from descendants.

Summary bars may visually overlay critical child work.

---

# Milestone Behaviour

Milestones may become Critical.

Example

Task A

↓

Release Milestone

↓

Task B

The milestone participates in scheduling exactly like a zero-duration task.
