# RAID Management

## Purpose

Provide an outline for using PM Platform RAID management capabilities.

## Scope

This guide covers risks, assumptions, issues, dependencies, comments, ownership, status, severity, priority, and project-scoped RAID workflows.

## Audience

Project managers, PMO analysts, delivery leads, risk owners, issue owners, and executives.

## Overview

RAID Management provides structured tracking for delivery risks, assumptions, issues, and dependencies. The register supports project governance, executive visibility, and consistent follow-up.

## Contents

### Introduction

Use RAID Management to identify, assign, update, and monitor project delivery concerns and dependencies.

### Prerequisites

- Access to the relevant project.
- Permission to view or manage RAID items.
- Defined project owners or team members for assigning ownership.

### Step-by-step Usage

1. Navigate to the RAID area or a project-specific RAID view.
2. Select the relevant RAID type.
3. Create a new risk, assumption, issue, or dependency where permitted.
4. Assign an owner.
5. Set severity, priority, status, and due date where applicable.
6. Add mitigation or resolution notes.
7. Review comments and history.
8. Close or update items as project conditions change.

### Troubleshooting

| Issue | Recommended Action |
| --- | --- |
| Cannot see a RAID item | Confirm project access and RAID visibility rules. |
| Cannot assign owner | Confirm the owner is an eligible project user. |
| Status change is unavailable | Confirm manage permissions for the RAID item. |

### FAQ

| Question | Answer |
| --- | --- |
| Are RAID dependencies the same as planning dependencies? | No. RAID dependencies are governance records; planning dependencies are schedule edges. |
| Can RAID items affect project health? | Yes, open risks and issues can contribute to health indicators. |
| Is history tracked? | RAID history is intended to support auditability and governance. |
