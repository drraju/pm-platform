# v1.1.0 Planning Workspace

## Purpose

Document the architecture of the v1.1.0 Planning Workspace foundation.

## Scope

This document covers the workspace read model, planning snapshot tables, Gantt visualization, dependency controls, resource allocation overlay, and known limitations.

## Audience

Product managers, engineering leads, backend engineers, frontend engineers, QA engineers, and PMO reviewers.

## Overview

The v1.1.0 Planning Workspace introduces a project-level planning experience backed by schedule snapshots. It allows users to view a hierarchical plan, inspect a Gantt timeline, create task dependencies, see critical path indicators, and view early resource allocation signals without directly mutating execution task records from the workspace UI.

## Contents

### Workspace Architecture

```text
Next.js Planning Page
  -> PlanningWorkspace component
  -> frontend API client
  -> NestJS PlanningController
  -> PlanningService
  -> schedule_snapshots
  -> planning_task_schedules
  -> task_dependencies
  -> resource_allocations
```

### Data Model

| Table | Purpose |
| --- | --- |
| `schedule_snapshots` | Stores project-level planning snapshot metadata and calculated schedule summary values. |
| `planning_task_schedules` | Stores task-level schedule rows for the active snapshot. |
| `task_dependencies` | Stores task-to-task dependency edges. |
| `resource_allocations` | Stores early task-level allocation percentages by user. |
| `resource_capacities` | Reserved for future capacity planning. |

### UI Composition

```text
Planning Workspace
|-- Header and zoom controls
|-- Task tree grid
|-- SVG Gantt timeline
|-- Dependency creation form
`-- Dependency list
```

### Current Capabilities

- Project-scoped planning workspace route.
- Task hierarchy display.
- Gantt bars for standard, summary, and milestone rows.
- Pointer-based task move and finish-date resize.
- Dependency create and delete.
- Basic circular dependency prevention.
- Critical path highlighting.
- Resource allocation display.

### Known Limitations

- Critical path is a foundation indicator and not a full CPM calculation.
- Schedule edits do not yet enforce dependency constraints.
- Workspace reads currently recalculate persisted critical path state.
- Gantt rendering needs virtualization for large schedules.
- Resource allocations do not yet calculate capacity or over-allocation.
- Pointer drag interactions need keyboard-accessible alternatives.

### Enterprise Readiness Notes

The workspace is suitable as a planning foundation and review surface. Before Resource Management depends on it, v1.1.1 should stabilize scheduling correctness, transaction boundaries, recalculation behavior, and large-plan performance.
